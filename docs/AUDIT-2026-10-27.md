## 2. Blocker crawler — hasil reproduksi nyata

Diuji pakai crawler apa adanya (`headless: "new"`, UA default, tanpa stealth), lalu diuji ulang
dengan lapisan stealth minimal (UA Chrome asli, `--disable-blink-features=AutomationControlled`,
override `navigator.webdriver/languages/plugins`, viewport 1440x900).

| Situs | Crawler sekarang | Setelah stealth patch | Akar masalah |
|---|---|---|---|
| `tokopedia.com` | **GAGAL** `net::ERR_HTTP2_PROTOCOL_ERROR` (237 ms) | 200 OK (8,1 s) | deteksi bot di level TLS/HTTP2 |
| `x.com` | **GAGAL** 403 → `chrome-error://chromewebdata/` "Access to x.com was denied" | 200 OK (6,7 s) | fingerprint headless + geo/UA |
| `instagram.com` | 200 tapi **cuma login wall** (body 848 char, 3 input) | sama | butuh sesi login |
| `traveloka.com` | 200 OK tapi **9,3 s**, mendekati batas `timeout: 30000` | — | `networkidle2` rapuh |
| `weebcentral.com`, `fmhy.net` | jalan (sudah ada di `reports.json`) | — | — |

**Kesimpulan:** mayoritas "blocker" bukan satu masalah, tapi 4 kelas masalah berbeda:

1. **Bot/WAF fingerprint** → bisa diatasi tanpa tool berat (stealth layer + fallback HTTP/1.1).
2. **Auth wall** → tidak bisa diakali; harus sesi login manusia (headed + persistent profile).
3. **Timeout/`networkidle2`** → situs modern (analytics, websocket, long-poll) jarang idle, jadi crawl
   mati total dan **tidak menyimpan apa pun** karena `try/catch` membuang semua data.
4. **Gagal parsial yang tidak dilaporkan** → user cuma lihat "Fatal error", tidak tahu kenapa.

## 3. Temuan fungsional penting (bug, bukan sekadar improvement)

### 3.1 Production build menyajikan data statis yang basi ⚠️ HIGH
- Frontend mengambil findings dari `/data/reports.json` (file statis).
- Vite menyalin `public/` → `dist/` saat build (`dist/data/reports.json`).
- MCP server & API menulis ke `public/data/reports.json`.
- Artinya pada mode produksi (`he-suite ui`, yaitu cara install yang dianjurkan README),
  **finding baru tidak pernah muncul di dashboard** sampai user build ulang.
- User stories aman karena lewat `/api/stories` (live). Findings tidak.
- Bukti: `dist/data/reports.json` = `public/data/reports.json` saat build; `express.static(distPath)`.

**Fix minimal:** tambah `GET /api/reports` (baca `public/data/reports.json`, `no-store`) dan ganti
`fetch('/data/reports.json')` → `fetch('/api/reports')`. Alternatif: mount `public/data` sebagai
static live di depannya `dist`.

### 3.2 Identitas report dari MCP rapuh
`mcp_server.js` menebak report berdasarkan `website === url` + window 2 jam. Kalau crawl kedua
di URL sama <2 jam, finding nyangkut ke report lama. `ID` finding = `"HE-" + Date.now().slice(-4)`
bisa duplikat tiap 10 detik. Tidak ada tool `get_reports` / `update_finding` / `delete_finding`,
jadi AI tidak bisa membaca/mengoreksi hasil kerjanya sendiri.

### 3.3 Crawler tidak menyimpan hasil parsial
Semua penulisan file ada di dalam `try`. Kalau navigasi timeout, `crawler_report.json` tidak
dibuat sama sekali — padahal console error & network failure sudah terlanjur ditangkap.

### 3.4 `process.cwd()` dipakai sebagai lokasi report
`crawler.js` menulis ke cwd dan `mcp_server.js` membacanya dari cwd. Kalau `he-suite HE <url>`
dijalankan dari folder lain, report hilang/tidak ketemu. Harus ada workspace/session dir tetap.

### 3.5 Belum ada trigger crawl dari UI
Dashboard hanya menampilkan hasil. Untuk crawl, user harus keluar ke terminal (`he-suite HE <url>`).
Ini gap UX terbesar: alat evaluasi tanpa tombol "evaluate".

## 4. Kualitas data untuk AI (kenapa hasil HE terasa dangkal)

`crawler_report.json` saat ini hanya berisi: `consoleErrors`, `networkErrors`, `pageErrors`,
daftar `input` & `button`, plus 6 file KMS. Untuk evaluasi heuristik yang serius, bukti yang
diperlukan belum ada:

- teks & struktur halaman (heading, landmark, label, alt)
- accessibility tree (`page.accessibility.snapshot()`) untuk hierarki fokus
- hasil audit otomatis (`axe-core`): kontras warna, label form, tap target, ARIA invalid
- computed style untuk kontras & ukuran target sentuh
- focus order & keyboard reachability
- screenshot per viewport (desktop/tablet/mobile), bukan satu PNG raksasa full-page
- screenshot per section (supaya bisa dipakai sebagai bukti pada finding)
- state sebelum/sesudah aksi (flow login, submit form)

Tanpa ini, AI hanya bisa menilai dari satu gambar dan daftar tombol → finding cenderung generik.

## 5. Keamanan — temuan (security engineer)

| # | Severity | Temuan | Bukti / dampak | Fix |
|---|---|---|---|---|
| S1 | **CRITICAL** | Path traversal di `/api/kb/:filename` (GET/POST/DELETE) | Terbukti: `GET /api/kb/..%2F..%2Fpackage.json` → **200 + isi package.json**. POST = tulis file sembarang (bisa timpa `.git/hooks` → RCE), DELETE = hapus file sembarang | `path.resolve` + cek `startsWith(kbPath)`, `path.basename`, whitelist `.md` |
| S2 | **CRITICAL** | Web terminal tanpa auth + CORS `*` | Server bind ke semua interface, `/api/*` terbuka untuk origin mana pun, WebSocket tanpa cek `Origin`. Halaman web jahat bisa `ws://localhost:8888` lalu kirim `{type:'input'}` ke `freebuff`/`agy` → eksekusi perintah di mesin user | bind `127.0.0.1`, token per-sesi (print di terminal, disuntik ke halaman), cek `Origin` di WS, CORS hanya `localhost` |
| S3 | HIGH | `/api/agents/launch` pakai `exec` + string interpolation | `start cmd /k "cd /d \"...\" && freebuff"`; `__dirname` tidak di-escape | `spawn` tanpa `shell: true` |
| S4 | HIGH | Tidak ada security header / CSP | `index.html` disajikan polos | `helmet` + CSP ketat (tanpa `unsafe-inline`) |
| S5 | HIGH | Tidak ada rate limit & batas body | `express.json()` default, endpoint tulis tanpa proteksi | `express-rate-limit`, `json({limit:'256kb'})` |
| S6 | MED | Password crawler via argv | `he-suite HE url -p secret` → terlihat di process list & shell history | env var / prompt tersembunyi, jangan pernah di-log |
| S7 | MED | 15 CVE dependency (3 critical) | `npm audit`: `concurrently`, `shell-quote`, `proxy-addr` critical; `body-parser`, `vite`, `puppeteer`, `@modelcontextprotocol/sdk` high | upgrade / buang `concurrently` dari dependencies runtime |
| S8 | LOW | `xterm` & `xterm-addon-fit` deprecated | paket lama, tidak dirawat | pindah ke `@xterm/xterm`, `@xterm/addon-fit` |

Catatan bagus: `.gitignore` sudah mengecualikan config MCP berisi path (walau bukan secret nyata),
dan `safeWrite` (tmp + rename) sudah benar untuk atomic write.

## 6. UX / UI (UX designer)

**Dashboard**
- Tidak ada filter/sort/search findings; 20+ finding sudah susah dibaca, apalagi 100.
- Tidak ada matriks severity × heuristic, tren per website, atau ringkasan per user story.
- Finding tidak punya bukti visual (screenshot/selector) → sulit dipercaya stakeholder.
- Belum bisa edit/hapus finding dari UI (hanya lewat MCP).
- Export hanya JSON mentah; tidak ada PDF/CSV/HTML report yang siap dikirim ke klien.
- `new URL(r.website).hostname` bisa throw untuk report dengan `website: "Unknown Website"` → white screen.

**Alur**
- Tidak ada "New Evaluation" (URL + kredensial + pilih user story + mulai) dan tidak ada progress.
- Status crawl tidak terlihat; user tidak tahu apakah masih jalan, timeout, atau diblokir.
- `alert()`/`confirm()`/`prompt()` dipakai untuk konfirmasi → tidak konsisten, tidak accessible.

**Aksesibilitas aplikasi itu sendiri** (ironis untuk alat HE)
- Banyak `<div onClick>` (bukan `button`), tidak ada `role`/`tabIndex`/`:focus-visible`.
- Kontras teks muted `#94a3b8` di atas `#0b0f19` ≈ 5.9:1 (aman), tapi badge & border tipis sulit dilihat.
- Tidak ada skip-link, tidak ada landmark, tidak ada `aria-live` untuk status loading.
- `index.html` tanpa `lang` yang benar (masih `en`) & tanpa meta description.

**Struktur kode FE**
- `App.jsx` 807 baris, 5 "screen" dalam satu file, tanpa router (state `activeTab` saja,
  tidak bisa di-refresh/deep-link).
- `WebTerminal` hardcode `ws://${hostname}:8888` → rusak di belakang proxy/HTTPS.
- Tidak ada error boundary, tidak ada loading skeleton, tidak ada toast.
- Nol test. Ada `oxlint` tapi tidak dijalankan di CI.

## 7. Backend / arsitektur

- **Storage:** JSON file + read-modify-write tanpa lock. Dua penulisan bersamaan (UI + MCP) bisa
  saling menimpa. `safeWrite` mencegah korupsi file, bukan lost update.
- **Tidak ada job model:** crawl dijalankan sebagai proses CLI terpisah, tidak ada queue,
  tidak ada cancel, tidak ada concurrency limit, tidak ada timeout global.
- **Tidak ada API untuk findings** (read/write/update/delete) — semua lewat MCP saja.
- **Tidak ada `/api/reports`** (lihat 3.1) dan tidak ada hapus report.
- **Tidak ada test & CI**; `build` menghasilkan warning chunk size.
- `PORT` hardcode 8888 (bisa bentrok); tidak baca env.

## 8. Usulan roadmap

### Sprint 0 — "Biar bisa dipakai" (½–1 hari)
1. Fix 3.1 `/api/reports` live (findings muncul di produksi).
2. Fix S1 path traversal + S3 spawn tanpa shell + S4 header dasar + bind `127.0.0.1`.
3. Fix 3.3 crawler simpan hasil parsial (navigasi gagal tetap menulis report + alasan).
4. Fix 3.4 workspace dir tetap (`.he-suite/sessions/<id>/`).
5. Fix crash `new URL()` di dashboard.
6. Hapus `.tmp/` probe, jalankan `npm audit fix` yang aman.

### Sprint 1 — "Crawler tahan blokir" (2–3 hari)
7. Stealth layer (sudah terbukti: tokopedia & x.com lolos) + fallback HTTP/1.1 otomatis saat
   `ERR_HTTP2_PROTOCOL_ERROR`.
8. `domcontentloaded` + adaptive settle (max 15 s) + retry 2×, ganti `networkidle2` sebagai default.
9. Auto-scroll untuk lazy-load, auto-dismiss cookie/consent/chat overlay, cap tinggi halaman.
10. Mode sesi login: `--login` membuka browser headed, user login manual (termasuk 2FA/CAPTCHA),
    profil disimpan (`userDataDir`), crawl berikutnya pakai sesi itu. Ini yang membuka
    Instagram/LinkedIn/Shopee/internal apps.
11. Report blokir yang jelas: `blocked: {type: 'waf'|'auth'|'geo'|'timeout', evidence}` supaya UI
    bisa bilang "butuh login" bukan "fatal error".

### Sprint 2 — "Bukti yang cukup untuk HE" (2–4 hari)
12. Evidence bundle: AX tree, teks terstruktur, axe-core, computed style, focus order,
    screenshot multi-viewport + per section.
13. Journey/steps DSL: user story → langkah aksi (click/fill/expect) → screenshot & console per step.
14. MCP: `create_report(url)`, `add_finding(report_id, ...)`, `get_reports`, `update/delete`,
    plus validasi severity 0–4.

### Sprint 3 — "Produk" (1 minggu)
15. UI: "New Evaluation" wizard + progress via WS, filter/search/sort findings, severity matrix,
    evidence gallery, edit/delete, export PDF/CSV/HTML.
16. Router + pecah `App.jsx`, error boundary, toast, aksesibilitas (fokus, aria-live, kontras).
17. Storage → SQLite (better-sqlite3) + migrasi dari JSON; lock/transaction.
18. Auth token untuk API+WS, helmet/CSP, rate limit.
19. Test (vitest + supertest) & CI (build + lint + test).
